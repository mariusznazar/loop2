# Styleguide browser-view — design

Status: BLOCKED on acceptance of the role-preservation requirement after independent spec review; not implementation-ready. The four design directions retain provisional orchestrator go-ahead under the user's task-cycle delegation. This is not human approval.

Authoritative inputs: frozen `task.md`, accepted 2026-10-20; product base `dc1f9cf9e9f3713386b6059d8214e588c69e5ba8`; the-way `d829e3aa6242a9b8901274531dd82fd5c7d87628`; approved MVP definition 2026-10-13, source-only relationship. The task's Q1–Q19 and 22 accepted settlements remain authoritative. This spec chooses representations and verification interfaces; it does not replace their exact values or meanings.

## Intent and limits

Give existing loop2 screens the accepted dark appearance, one source of appearance values, six reusable native DOM controls, a local page showing their states, and enforceable guidelines for later screens. Success includes migrating all existing styles now and keeping gameplay, the current layout and focus-preserving updates intact.

This is architectural work under Superpowers brainstorming 6.4.1: shared component interfaces, asset delivery and check contracts are introduced together. The cycle replaces its human intermediate approval and default spec/plan destinations. No engine, gameplay, account-server behavior, future MVP screen or full WCAG AA implementation is added. No loop UI/engine source or prohibited 10x material is read. Source values are the task's recorded observations, not a new observation of the changing loop site.

## Chosen representations and alternatives

| Choice | Selected | Alternative and cost |
|---|---|---|
| Appearance values | `src/browser/view/design-tokens.json`, read at build time to generate CSS custom properties and font faces; authored `src/browser/view/styles.css` refers to those properties | CSS with source comments avoids generation but makes source/type extraction dependent on comment syntax; executable TS tokens introduce code execution into simple value checks. JSON adds a small deterministic emitter, but makes checks independent of CSS parsing for values |
| Fonts | Two unchanged variable WOFF2 files from the official Vercel repository at a fixed commit, vendored in `assets/fonts/`, with OFL and provenance | npm `geist` adds a package and audit surface for two files. Vendoring costs a deliberate update and narrow Docker copy change; no network is needed during build or play |
| State page | `tools/styleguide/` source, dedicated TypeScript configuration, output `.runs/styleguide/public/`, local command `npm run kitchen-sink` | Putting source under the game compiler risks shipping it; a third-party component explorer adds dependencies and framework concepts. Dedicated compilation adds one configuration but uses the already installed compiler |
| Recognition for checks | Six named exported factories registered in `controls/index.ts`; actual DOM construction tested; state-page fixtures identify control and state | Checking only labels or manifest counts could pass a blank page. Full browser automation would be stronger for pixels, but the foundation has no established agent browser route, and this task does not make that a prerequisite |

Leaving the current files unchanged retains the task's four observed failures and does not satisfy the task. These choices are reversible through local code changes; no new external account, hosted service or deployment operation is required.

## 1. Values and style delivery

`design-tokens.json` is the only authored source of appearance values, except the task's explicit icon exception. Its top-level `roles` is an object keyed by exactly the task's 23 role names. Each entry contains `kind`, `value`, and a nonempty `source`. Kinds are exactly `background`, `text`, `other`. `depleted` carries opacity, not an invented color. All other role values are the accepted colors. A separate `tokens` object carries non-role values: font families, six text sizes, seven spacing steps, two weights, frame and bar widths, character/step/link widths, step dash pattern, focus width and offset. Every such record also has `value` and `source`. Names are stable semantic names and values remain independently editable even when equal.

The token author copies exact values and sources from Q9–Q11/Q19, including each observed loop element, observation date and public URL; adjusted values cite the Q8 contrast criterion and the change; selected preview values cite the accepted Q10 choice; spacing cites Q11/Q19. No temporary report is a required source. Numeric CSS values retain their units where required; SVG dash lengths and opacity retain the accepted unitless representation. JSON structural keys, names and source strings are metadata, not extra appearance values.

`scripts/style-assets.mjs` validates the shape and emits `design-tokens.css` into a caller-owned output directory. Role variables are `--<role>`; supplementary variables are `--<token-name>`. Role/token names may not collide. The emitter handles only documented literal values, never evaluates source code and never interpolates unvalidated strings into CSS. It emits font faces using the family and weight records from the same JSON file. Font paths are relative same-origin asset paths; no CDN or runtime font download from another origin is introduced. The generator copies the authored stylesheet and the fixed font/license files. Generated output is untracked and outside the browser-view source scan.

The normal build still compiles both existing TypeScript configurations, then copies HTML, icons, fonts and styles. `index.html` links generated tokens before authored styles; its existing embedded style block moves to `styles.css`. No browser JSON loader or startup fetch is needed. Build output must be deterministic for the same input values. A missing or malformed token/font is a build failure rather than a silently omitted asset.

All existing styling moves to tokens under Q15's exact exceptions. Preserve the current columns, breakpoint, terrain geometry and layout dimensions. Existing non-scale spacing maps to the nearest accepted spacing, ties upward. Use accepted sizes by purpose: body/menu, buttons/descriptions, headings, labels, game title and map title. Existing line-height may remain unitless because Q15 names line thickness, dash pattern, opacity and font weight as the unitless appearance restrictions; if a new line-height choice becomes necessary, retain the current value rather than invent a redesign. Radius and shadow are absent/none, as accepted.

## 2. Shared native controls

`src/browser/view/controls/` provides six semantic factories, with their registry exported by `index.ts`: ordinary button, destructive button, selected group button, select, number field and text field. Files may share private construction helpers; the registry is not six copied implementations. Controls are native `button`, `select` and `input` nodes using DOM APIs, with one shared class and semantic variants. No UI framework and no custom replacement for native select behavior.

Button factories return the native button. Fields return a native control plus a containing element and an error-state setter where a message below the field is needed. Their caller can read/write the native value and attach the existing listeners. Expose normal attributes through typed arguments or the returned native node, without inventing gameplay validation. Error state uses `warning`, `aria-invalid` and an associated visible message; clearing the state removes that association. Empty inputs use the label-text role for the placeholder; empty select has no real choices. A selected button exposes its selected state to accessibility APIs. Disabled means native disabled and the disabled-text role, and wins over destructive/selected text styling.

Default background is transparent with ordinary text, except selected strong text and destructive danger text. Hover uses `highlight` without changing the frame. Focus is a distinct outline with the focus token, width and offset from Q10. The universal `:focus-visible` rule applies to all keyboard-focusable elements, including footer links and future native controls; focus is not limited to the six factory classes.

Migrate `program-editor.ts`, `status-row.ts` and `send-panel.ts` to the factories. “Zakończ”, “Usuń” and “Restart” use destructive buttons. Keep existing callbacks, numeric commit/clamping behavior, resource-option population and focus restoration. The refactor must not rebuild a focused control on clock ticks. A generic text field is demonstrated locally; it does not add a text-expression condition to the game. No loading behavior is invented.

## 3. Terrain, typography and assets

Keep the terrain model and hover-only interaction. The tile body uses hidden/revealed roles and both states use `tile-edge`. Character and step target use the same `character` role, with their distinct exact widths and dash pattern from Q19. Link hover adds a separate thin outline to the tile and a line at the row's left edge, without repainting the tile. The DOM must allow character/step and link outlines simultaneously; geometry may inset the link outline to keep both recognizable. Preserve top-layer character/step outlines and pointer-event behavior. Depleted icons use the `depleted` opacity. Stock remains in the list.

Every SVG icon becomes the accepted strong-text color, keeping its safe SVG content and attribution unchanged except the exact change description “zmienione (bez tła, jasny kolor)”. This is the explicit Q15 exception; a token-value change later requires updating these files manually.

Vendor the official `vercel/geist-font` release v1.8.1, resolved on 2026-10-20 to commit `e1f671c727f6de7e97c1e1d26dbb44f349c19459`. Confirmed upstream paths:

- `fonts/Geist/webfonts/Geist[wght].woff2`
- `fonts/GeistMono/webfonts/GeistMono[wght].woff2`
- `OFL.txt`

Use stable local names `assets/fonts/Geist.woff2` and `assets/fonts/GeistMono.woff2`, unchanged file bytes, plus `OFL.txt` and `SOURCE.md` recording pinned raw URLs, version and measured SHA-256 hashes. Download each named file directly, without executing upstream scripts or extracting an unrestricted archive. Check nonempty WOFF2 headers and matching upstream bytes/hash, reject an HTML error body and unsafe font paths. Preserve the upstream license, whose copyright and license must accompany distribution. The copied result includes OFL. Use the existing compiler and no font npm dependency.

Official sources: [repository](https://github.com/vercel/geist-font), [release](https://github.com/vercel/geist-font/releases/tag/v1.8.1), [pinned OFL](https://raw.githubusercontent.com/vercel/geist-font/e1f671c727f6de7e97c1e1d26dbb44f349c19459/OFL.txt).

Geist is the normal UI face. Geist Mono applies to the existing passage clock/status time and any existing chronicle text; the task adds no chronicle if absent. Use only the accepted text weights. `Dockerfile` gains a narrow copy of `assets/fonts/`; `.dockerignore` admits that directory, leaving unrelated asset directories excluded. The normal image receives only normal build output.

## 4. Local page and command

`tools/styleguide/index.html`, `main.ts`, a page module and a page-only stylesheet comprise the page. `tsconfig.styleguide.json` compiles its TS and imported browser controls with the existing installed TypeScript 7 compiler, using a root that preserves imports and an output under `.runs/styleguide/public/`. The ordinary browser config remains scoped to `src/browser/**/*.ts`. The page imports controls directly, not the game entry point, app, simulation runner or account server. It may read the content catalog to obtain an icon/name; examples never hardcode game identifiers outside data.

`npm run kitchen-sink` runs `scripts/kitchen-sink.mjs`: build the standalone output, bind a temporary server only to `127.0.0.1`, print its URL and open that URL with the platform's normal browser launcher. `--build-only` produces artifacts and exits for checks; `--no-open` serves without launching for automation. Reuse current Node and compiler. The command serves only the standalone output directory, handles URL decoding and rejects traversal/symlink escape; no repository-root serving or proxy to the account server. Use an OS-selected free port, close on interruption, and report launch failure with the usable URL. Browser launch is a convenience, never a successful-render verdict.

The page creates one section for each of the six factories and seven named state cells per section. Each cell contains the actual shared control in that state or visible nonempty text explaining inapplicability. Error/empty are inapplicable to buttons; loading is inapplicable to all six until a server-waiting control exists. Native default, disabled, empty and error state are set through real component APIs. Multiple hover/focus examples use page-only preview selectors, with the same declarations as the real shared pseudo-state styles, checked for agreement. They are clearly demonstrations, not a claim that multiple elements hold actual keyboard focus.

Each cell has `data-control` and `data-state` for inspection. A cell marked as rendered must actually contain the corresponding native element; a reason-only cell cannot pass as a rendered state. Registry discovery and exported factories are checked so deleting a registry row cannot silently reduce coverage. Tests execute page construction through a small recording DOM harness; they inspect actual nodes, native attributes, error text and styles. This is structural execution, not a layout engine.

The page also renders all 23 roles from the token data, typography/spacing samples, and static tile samples: hidden, revealed, link hover, character, step target, depleted icon and relevant combinations. These samples are plain role-driven SVG shapes, never a game-state fixture passed to `terrainPicture()` or the game renderer. No controls for changing live gameplay state exist there.

Extend ESLint typed programs/browser globals, formatter discovery and ownership to `tools/styleguide/**` and the new configuration. Amend the whole-file ESLint guideline cases if changing that configuration makes them stale. Do not change the adopted rule set or add a compiler package. Browser-module guidelines apply to the shared controls in `src/browser/view/`; the page itself remains covered by the general coding guidelines.

## 5. Check contracts and independence

The foundation author, invariant-check author and product-code author must be different agents. Names below are proposed identifiers/interfaces for the foundation writer to settle through the required skills; the spec itself writes no binding sentences. Mechanical methods use the existing Python quality adapter pattern where useful: exit 0 is a proved pass, 1 a proved violation, 2 inability to decide with no successful invariant verdict. Each method accepts `--record` and records the final invariant identifier/version. Paths/commands must be reconciled with the actual implementation before the foundation is finalized.

| Proposed check interface | What it establishes |
|---|---|
| `python -B scripts/check_styleguide.py --check tokens --record <path>` | All files owned by browser-view are discovered, including new paths. In source CSS, embedded CSS and style-bearing TS strings/DOM operations, detect all Q15 prohibited color forms, lengths, font names and specified unitless appearance values. Allow only Q15 exceptions, the sole JSON token source and icon files. Scan source tests as part-owned files too; comments and non-style numeric data are not style declarations. No per-file historical allowances |
| `... --check focus` | Universal real `:focus-visible` rule resolves to the focus role and exact token width/offset; all keyboard-focusable construction paths are covered, links included, and no loaded stylesheet, inline style, generated style mutation or custom-property override disables it. Check outlines/longhands, aliases, `all`, opacity/visibility, clipping and conditional rules that can defeat the indicator. Unsupported dynamic style generation or unhandled CSS syntax yields inability, never an omitted file or pass |
| `... --check contrast` | Compute sRGB contrast from the token values: every text role except disabled against all three backgrounds; control border and focus against the three backgrounds; character against hidden/revealed tiles and tile-edge where touching; hidden versus revealed tiles. Include any other actual adjacent color introduced by implementation. No rounding before threshold comparison. Disabled text and depleted icons are reported as exempt |
| `... --check states` | Compile the standalone page, execute its actual page/control construction and inspect all six-by-seven cells, native element identity/state and nonempty reasons. Compare real and demonstrated hover/focus declarations. Missing factories/cells, merely claimed states, wrong disabled/error state or orphaned error messages fail |
| `... --check roles --fork-point <commit>` | Read names and kinds from the token file at the explicit fork point and current tree; existing names/kinds remain. A confirmed absent token file on this task's fork point is an empty prior set, not a git failure. Unreadable commit/file or malformed data does not pass. Role schema still requires all 23 task roles on the first implementation |
| `... --check sources` | Every actual appearance value record in the token source has an adjacent nonempty source; nested records/dash parts are not omitted, unknown schema or hidden value-bearing fields cannot bypass it. This checks presence, while review checks truth of attribution |
| `... --check production` | Run the real ordinary build, inspect actual `dist/public` output and the HTML/module/style reference graph. No page entry, page-only stylesheet, fixture/manifest or other state-page artifact is included. Exercise ordinary build after a standalone build and with stale output seeded so a copying or cleanup regression is detected. Merely checking the compiler include list is insufficient |
| Foundation agent method, 2 of 3 independent reads | Each role use in every browser-view file has its decision's meaning; three independent readings on the final range, with at least two compliant results. Cases are exercised using the same method; a script cannot substitute semantic name matching |

Source discovery must follow the part map, not a fixed list of the original files. Use existing TypeScript AST facilities for literal extraction and a deliberately bounded CSS analysis that handles the product's real syntax; do not claim a general JavaScript/CSS proof. Any inability is explicit and blocks acceptance of that method until the implementation or analysis makes the actual source decidable. Comments, paths, ordinary prose mentioning a color, and SVG geometry must not be mistaken for appearance declarations. CSS escapes, function colors, named/system colors, shorthand values, inline styles and custom-property overrides are adversarial cases for the checker. No checker treats a metadata claim of coverage as proof.

The focus method implements the exact agreed structural invariant (“has focus style and nothing disables it”). It does not establish browser rendering, offscreen overlap or every platform's select popup painting. The code reviewer separately checks the whole UI change and reports visual evidence available through the cycle. D-19 establishes no agent browser route: missing screenshots remain explicitly unchecked, never replaced by source review or DOM-harness output.

Add behavior tests for preserved button callbacks and numeric commit rules, disabled/selected/error states, focus identity through updates, simultaneous tile outlines, unchanged stock location, source generation, copying font/license bytes and nonshipping of the page. Tests for check tools include deliberate adversarial inputs and checks that missing data/tool failure cannot pass. Font and preview-server trust boundaries receive header/path/traversal tests. Reuse the existing game tests for gameplay rather than duplicating them.

Each new script invariant gets an independently authored deliberate break and a reviewer-observed failure. Each guideline rule naming an invariant gets one whole-file good/bad case per invariant; good strictly passes and bad fails on the checked commit. Do not weaken “no literal values” cases into relative-to-baseline comparison. The background/text form rule keeps descriptions only.

Role-preservation acceptance is BLOCKED. The actual fork point `dc1f9cf9e9f3713386b6059d8214e588c69e5ba8` contains no roles, so the agreed invariant that no role from that fork point changes name or kind is vacuously true for this first introduction. No whole-file bad case can violate that sentence against this actual base. A synthetic base containing roles can provide ordinary checker unit-test evidence, but cannot replace the actual fork point or satisfy the mandatory guideline-case acceptance. A schema failure, missing newly introduced role or inability to parse also does not prove violation of the historical-preservation sentence. Resolving this conflict requires the owning workflow's decision; implementation must not proceed on a fabricated passing acceptance.
