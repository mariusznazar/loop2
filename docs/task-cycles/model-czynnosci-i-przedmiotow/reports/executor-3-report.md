## Choices

- Expected fingerprint computed with `contentFingerprint(...)` on the judged program, the case's own program, as the slice's "the expectation built from the program the case judged" reads. Rejected: a literal 16-hex constant per case, copied from a run. The literal would be independent of the function, but it is an opaque hash that breaks on every change of the hash's inputs and has to be regenerated by running the code; the cost of the chosen way is noted under concerns.

## Concerns

- The guideline `guidelines/testing.md` ("Where the expected value comes from", "Test inputs and expected values") asks for expectations derived without the code under test. Here the fingerprint expectation comes from `contentFingerprint`, the function under test in `judging-record.ts`. These two cases therefore cannot catch a wrong hash; a wrong hash is caught only by the tests of the function itself (Slice 1's tests, not read by me). If the orchestrator wants an independent expectation, the alternative is a literal hash per case, decided by the human or as a follow-up.
