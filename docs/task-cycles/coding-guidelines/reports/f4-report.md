## Choices, alternatives and costs

- Direct per-file API formatting avoids ignoring new owned files; CLI glob/check output alone could appear green after an accidental ignore. Cost: an embedded Node bridge and explicit output validation, plus one formatting operation per file. The fixture uses real Git discovery, Node process execution and bridge code with a miniature local formatter module because the adopted tool is not installed. It tests our adapter's scope/verdict boundary, not Prettier's parser implementation.
- Compare resolved options to the pinned formatter's complete default metadata instead of maintaining a second hand-copied full option table. A six-setting-only check would allow changes such as experimentalTernaries or trailingComma to slip through. Cost: trust in the pinned tool's supported metadata API, whose live compatibility remains unchecked until installation. The six explicit D-32 settings remain independently literal, so malformed/mismatched default metadata cannot silently change them.
- Resolve editor behavior separately rather than merely forcing root configuration and ignoring EditorConfig. Otherwise an editor can produce different indentation while the gate checks defaults. Cost: a second configuration resolution per file; a local nested/editor override can now stop the check until reconciled with the one adopted effective configuration.
- Validate UTF-8 before Node reads the file. Node's replacement decoding can turn invalid bytes into a matching formatted string, even though rewriting would alter bytes. Rejecting unreadable inputs prevents that false success at the cost of one additional source read. The test caught this actual weakness before the fix.
- Check effective LF checkout attributes as well as current CR bytes. Merely seeing LF once on one host does not establish cross-platform preservation. Cost: an extra Git invocation and validation, and a missing attribute is a proven policy violation even if current bytes happen to be LF.
- Inline `prettier-ignore` is not newly banned. Root clarified that D-32 adopts native pinned formatter behavior and forbids leaving historic files outside the one-time scope, without establishing a new source-directive prohibition. This clarification is recorded as an interpretation for independent review, not a review verdict. Full file enumeration and raw LF enforcement still apply to such files.
