## Slices

### Slice 1 — A manual map run keeps its record of the end, and the save is version 4

- **Goal:** A manual map run keeps, from its start to its end and through the saved document, what the end of the map run needs, and the document is version 4. In `src/browser/sim/types.ts` the type `GameMapRun` gains three fields: `longestStreak` (the greatest value `streak` held at the end of a game minute of this map run; at least `streak`, at most `minute`), `minutesByAction` (the game minutes of the map run by what the character was doing, a record over a closed list — the kinds of the data's ordinary actions (those of the type `Action` that are not combat-only), `wait` and `combat`; each game minute passed counts once, to what the character was doing at its start — `combat` while a fight goes on, else its current activity's action kind or `wait` — so the counts sum to `minute`, the game minute of a death and of a completion included) and `enteredWith` (the entries `{item, count}` of the backpack the send gave the character, in the order of the data's items, none with count 0; bound when the map run starts and again at „Restart”, kept unchanged to the end, in the saved document and back). A new file `src/browser/sim/run-record.ts` holds the pure functions that give a record its start from the entry backpack and give its next value from the map run before a game minute and after it; `startRun` in `src/browser/sim/game.ts` binds the record, `advanceMinutes` updates it after every game minute it passes and carries it into the map run it returns, and `restart`, `end`, `settleDeath` and the editing functions leave it as they find it. Earning loops (the plain `MapRun`) keep none of it and `src/browser/sim/run.ts` is not changed. `SAVED_GAME_VERSION` rises from 3 to 4 in `src/browser/sim/saved-game.ts` (D-206), the document of the load reads the three fields strictly under `guidelines/coding-saved-game.md` — every key present and no foreign one, the keys of `minutesByAction` from the closed list, counts safe whole numbers, the sum equal to `minute`, `longestStreak` inside its bounds, `enteredWith` read as the lists `tripList` reads with an item of the data and a count from 1 — and a document of version 3 is refused whole as `version`. A map run that ended in death or a completion loads back whole with the three fields (To do 10). The list of the fields a `GameMapRun` adds to a `MapRun` in `tests/sim/loop.test.mjs` gets the three. The change touches the trust boundary of the part, so it gets a review of its own.

### Slice 3 — The end-of-run window as a component, with its look

- **Goal:** The window exists as the React component `EndWindow` in the new file `src/browser/view/end-window.tsx`, drawing from a game state holding an ended map run, from the entries of „Ostatnie minuty” the screen gives it and from the controls the screen gives it (close, restart, end, open the map named, add the rule of the discovery). It is a column in a `section` with `role="dialog"` named by its title: at the top the label „Koniec przejścia”, the title of Slice 2 and „✕” (the shared button with `label` „Zamknij okno”); in the middle the scrolling part; at the bottom the buttons, which do not scroll. The scrolling part answers in order what happened (the longest streak under the title, drawn as the bar of the header's requirement with the same classes and `--share`; then the discovery text in `discovery` with „Dodaj regułę z tym” where a discovery stands, no „Wznów”), what it cost or gave (the line of Slice 2), why (each section only where it has content, each name in `text-label`, in this order: „Ostatnie minuty”, the paragraph of the last encounter in `text` composed with `combatText` from the map run's `lastCombat` where the map run had an attack, „Nie zadziałały ani razu”, „Na co poszedł czas” as one bar with a legend of the names and percentages, „Wyprawa i teren”), and what next at the bottom („Restart” with the warning of a cut trip plan beside it as the header gives it, „Zakończ”, and after a completion „Otwarte: {mapa} →” for each map Slice 2 names; „Restart” and „Zakończ” are the shared destructive buttons, „Otwarte” the plain one). Keyboard: Escape pressed inside the window asks to close it through the control, as the rule panel does; when the window appears, focus moves to it; the window traps nothing, since the menu bar above it must stay reachable. The component draws nothing for a state without an ended map run. In `src/browser/styles.css` the window takes: the width of the screen's content column and a `max-height` in `vh` (a layout dimension D-43 leaves out; the executor names the figure it takes and checks it at 1280 × 720 and in the one-column layout under 1074 px); the background `panel` with its text in `text`, a frame in `divider`; the middle part `overflow-y: auto`; fonts and sizes from the existing tokens; the bar of time as a track in `highlight` with each piece filled in `text` and a gap of `--frame-width` between pieces, the legend beside or under it in the same order of pieces. No value is added to `src/browser/tokens.css` and none is chosen: the bar's pieces need a way to be told apart by more than their order, and the window needs no backdrop since it covers the screen; the executor names in its report each value the token file lacks and the styleguide's roles do not give (`src/browser/AGENTS.md`).
