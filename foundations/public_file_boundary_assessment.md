# Public file boundary assessment

Assess `public-file-boundary/1` on one named product commit. The question is whether every static file the server can send comes from that commit's built `dist/public` directory, regardless of the process working directory. A passing sample request alone does not settle this question.

1. Record the full commit SHA. Install its locked dependencies with `npm ci`, build it with `npm run build`, and inspect the built server as well as the TypeScript source and build script. Identify the directory that becomes `dist/public` and how the running server resolves it from a foreign working directory.
2. Trace the complete server entry point, imported application modules, registered middleware and routers, and every reachable response path. Include parameterized and nested routes, non-GET methods, branches selected by headers, cookies, body, authentication, time or state, and any late route registration. Inspect the locked serving dependencies, including Express and its file-serving packages, where their behavior determines the selected path.
3. For every path that can transfer filesystem bytes to a response, including static middleware, `sendFile`, `download`, streams and reads followed by `send` or `end`, determine what it returns and the actual file or possible file set. Distinguish static file/asset serving from an account/save API response returning the requested application record, which may live outside `dist/public`; classify by the data returned, not the URL prefix or transfer API. A route that reads and sends an unrelated repository file such as `package.json` is still a file leak even if it is under `/api/` or wraps the bytes as data. Resolve roots, relative paths and symbolic links as the server will, and confirm that every static file target is within the built public directory. Internal reads whose bytes cannot reach a response do not violate this invariant; a public-rooted direct file response may comply.
4. Use `npm test` and `python -B .the-way/gate/run_tests.py tests/invariants --record .runs/invariant-tests.jsonl` as supporting evidence. Exercise public bytes, outside files, traversal and a foreign working directory. Review any routes or conditions those finite checks do not execute; do not infer that their passing result covers them.
5. Give `pass` only when the complete serving behavior and relevant dependency behavior at that commit support the sentence. Give `fail` for a reachable outside-public static file or disguised file leak. If the assessment is incomplete, record no verdict and report which paths or dependencies remain unassessed.

Record a completed human assessment in `foundations/human_verdicts.md` using the pinned the-way row `| Entry | Version | Verdict | By | On | Commit | Until |`: `public-file-boundary`, `1`, `pass` or `fail`, assessor, assessment date, assessed commit SHA, and `none` in *Until*. No row is written for an incomplete assessment. The verdict lapses when a later change reaches the invariant.
